## 進み方と強さ（数値の調整）

- 数値はすべて `game/data/balance.json` に置いてある。40HzP に「◯◯を△△にして」と頼まれたらここを直す。各項目の意味は設計書8章
- 設計書・設計ページと違う値：`time.gameHoursPerRealSecond` は 58.4（現実の1時間＝ゲーム内の24年）。設計の「現実1時間＝1年」（2.4333）を 40HzP の依頼で24倍速にした。最初の案内の「7歳まで約◯分」はこの値から計算して出す
- 魔物の強さと、次のLvまでの経験値の式は設計書8章と違う（40HzP の「20階層まで上がれない」で変えた）
  - 階層Fの魔物の数値＝ `monster.base` ＋ `monster.perFloor` ×（F−1）。1階層ごとに一定の量ずつ強くなる（設計の `growthPerFloor`・`hpGrowthPerFloor` の掛け算は外した）
  - 次のLvまでの経験値＝ `levelExp.base` × Lv^`levelExp.power`（今は Lv の2乗。設計の growth^(Lv−1) は外した）
  - 理由：主人公はレベルごとに足し算で伸びるので、魔物や必要な経験値を掛け算で増やすと必ず頭打ちになる（前の式では何時間遊んでも17〜19階層で止まった）。式を掛け算に戻さない
  - 目安（計算で再現。仲間を雇い、装備を買う）：勉強なしで20階層 約11分・40階層 約53分・60階層 約2時間6分。1分に1問正解すると20階層 約8分・40階層 約28分・60階層 約48分・100階層 約1時間39分・150階層 約2時間50分（2026-11-08 に、すばやさと運の良さを無くして（すぐ下）計り直した。その前（2026-11-07 に、やられたら1つ手前の階層から（下の「誕生日の熟練判定と階層の移動」）にしたとき）は勉強なしで20階層 約15分・40階層 約1時間6分・60階層 約2時間26分、1分に1問で20階層 約10分・40階層 約32分・60階層 約54分・100階層 約1時間39分・150階層 約2時間37分）
  - 遊んだ時間ごとのレベルは、2026-11-07 から約1割低い（そのときの計り直しで、勉強なしで60分 Lv49（前は54）・180分 Lv83（前は91）、1分に1問で60分 Lv70前後（前は76）。今は勉強なしで60分 Lv50・180分 Lv84、1分に1問で60分 Lv73・180分 Lv169）。前はやられると1階層（か拠点）から登り直していて、そのとき弱い敵をたくさん倒して経験値を稼いでいたため。階層の進み方はほぼ同じ（1分に1問なら少し速い）
  - `adventure.test.js` で「仲間も勉強もなしで1時間のうちに20階層を越え、30分〜1時間の間も進む」を確かめている。数値を変えてこのテストが落ちたら、頭打ちが戻っている
- 主人公と魔物のステータスの伸び方は3倍にしてある（40HzP の「数字が代わり映えしなくて退屈」で変えた）。`hero.perLevel` の全項目・`hero.wisPerCorrect`・`monster.perFloor` の hp・atk・def を3倍にした（初期値の `base` と、経験値・ゴールドの伸びはそのまま）
  - 進み方（何分で何階層）を変えないために、合わせて次も変えた：すばやさ・運の良さ1あたりの効き目を3分の1（どちらも今は無い。すぐ下）、装備（`items.json`）の攻撃・防御を3倍、小学校教師の強さを計算で合わせ直した
  - 伸び方をまた変えるときは、この組を同じ倍率で動かすと進み方が保たれる
- すばやさと運の良さは無い（40HzP の依頼「やっぱりすばやさと運の良さは無くして」。2026-11-08）。主人公のステータスは HP・MP・攻撃・防御・賢さ。主人公の攻撃は秒間2回で決まっている（`hero.attackIntervalSec`＝0.5）
  - 前は、すばやさが回避率（すばやさ×0.002、上限50%。冒険画面に MISS）、運の良さが会心の一撃（運×0.0017、上限50%、ダメージ1.5倍）と、倒したときのゴールドの増え方（運1あたり0.33%、上限なし）だった。その前は、すばやさは攻撃の速さだった。`balance.json` の `stats` と `hero` の `agi`・`luck`、セーブの `adventure.evadeAcc` を無くした（前のセーブに残っていても使わない。セーブの版はそのまま）
  - すばやさ・運の良さを足していた品は、ほかのステータスに付け替えた（下の「店（装備）」）。ツキノウミセツの水しぶきは、すばやさの代わりに攻撃を下げる（下の「月面」）。起動から3分の比較にも出さない
  - 進み方と中ボスに勝てるレベルを前に近づけるため、計算で合わせ直した：`hero.perLevel` の HP 14→23・攻撃 3.8→4.1、`monster.perFloor.gold` 1.4→1.75、中ボス9人の HP と攻撃（`monsters.json` の `stats`）、月面の倍率 `moon.rampTo` 1500→1400（下の「月面」）
  - 合わせ方：前の版と同じ遊び方（仲間を雇い、装備を買う。勉強なし・1分に1問・1分に2問）で、遊んだ時間ごとのレベルと最高階層を比べ、いちばん近い組を選んだ。中ボスは、目標の武器・防具で目標のレベルの9つ下〜2つ上と、鉄の剣・鉄の鎧のときに勝てる回数が、前の版とほぼ同じになるように HP と攻撃を合わせた
  - 違いが残ったところ：前の回避と会心は、レベルが上がるほど効いていた（回避はLv140ほどで上限50%＝やられにくさ2倍）。足し算の伸びでは同じ形にならないので、はじめは前より速く、たくさん勉強して長く遊ぶと少し遅い
    - 勉強なし：20階層 11分（前は15分）・60階層 2時間6分（前は2時間26分）。180分で Lv84・71階層（前は Lv83・67階層）
    - 1分に1問：20階層 8分（前は10分）・100階層 1時間39分（同じ）・150階層 2時間50分（前は2時間37分）。180分で Lv169・156階層（前は Lv166・165階層）
    - 1分に2問：180分で Lv218・208階層（前は Lv232・238階層）
    - 倒して得たゴールドの合計（180分）：勉強なし 25万（前は24万）・1分に1問 61万（前は67万）・1分に2問 77万（前は119万。前は運の良さによるゴールドの増え方に上限が無かった）
- 攻撃のテンポは一定（40HzP の依頼）：主人公の攻撃は群れが入れ替わるときも0.5秒ごとに途切れない。次の群れは、主人公の次の攻撃の `floor.spawnLeadSec`（0.35秒）前に出る（群れが右から出てくる動き（`render.js`、0.35秒）が終わったところに攻撃が当たる。もう間に合わなければすぐ出る）。敵がいない間も主人公と仲間の攻撃の拍は進め、相手のいない拍は見送る（`sim.js` の `spawnDelay`・`idleStep`）。前は群れを倒すと0.8秒あけて出し、出たときに主人公の拍を0.25秒に置き直していたので、群れの間だけ約1秒あいていた
  - 群れの間のすき間が無くなった分だけ進みが速くなる（約5〜10%）ので、ザコのHPの伸び（`monster.perFloor.hp`）を 39→43 にして（そのあと防御を下げたので今は49）、遊んだ時間ごとのレベルと最高階層を前の版に合わせた（中ボスは強さが決まっているので変わらない）。`group.test.js` が「攻撃の間隔が0.5秒のまま・群れは攻撃の0.35秒前に出る」を確かめる
- 敵の防御は低く、HPは多めにしてある（40HzP の依頼「成長によるダメージ量の増加が見えるように」）。ダメージ＝攻撃−防御×0.5 なので、階層とともに防御が伸びると、主人公が強くなってもダメージの数字が伸びて見えなかった
  - ザコ（と、ザコの数値に倍率を掛けるボス）：`monster.base.def` 1→0、`monster.perFloor.def` 1.5→0.3（5分の1）、`monster.perFloor.hp` 43→49。中ボス9人：防御を5分の1、HPを約1.6倍（`monsters.json` の `stats`）
  - 主人公のふつうの攻撃のダメージは、攻撃の数字からほぼそのまま（防御で引かれる分が、前は攻撃の2〜4割、今は1割以下）。レベルが上がった分だけダメージが増え、深い階層に進んでもほとんど減らない
  - 進み方（遊んだ時間ごとのレベルと最高階層）と中ボスに勝てるレベルは、前の版と同じになるように計算で合わせた（ザコのHPの伸び、中ボスごとのHP）

## 冒険画面の表示

- 冒険画面の獲得量は「1か月あたり 経験値・ゴールド」（ゲーム内1か月あたり。直近 `rateWindowSec` 秒の平均から出す。ゴールドは契約料を引く前）。その下の行に「契約料（1か月の合計）」と「手取り（ゴールド−契約料。マイナスなら赤）」を並べる。設計の「秒間獲得経験値・ゴールド」を 40HzP の依頼で変えた
  - 数字の色分け（40HzP の依頼「経験値を青文字、ゴールドを黄色文字、契約料を赤文字にして」「色を変えるのは数字だけでいい、文字は元の色に戻して」）：色を付けるのは数字だけで、「所持金」などの文字は元の色。経験値の数字（経験値の帯の右・累計経験値・経験値倍率・1か月あたりの経験値）は青、ゴールドの数字（所持金・1か月あたりのゴールド・会社の利益・手取り）は黄色、契約料の数字は赤。数字に付く「G」「×」「−」「+」も数字と同じ色。手取りがマイナスのときは数字が赤。冒険画面のステータスはどちらの画面の色でも暗い下地なので、明るめの色にした（CSS の `#hud .c-exp`・`.c-gold`・`.c-fee`）

## 勉強（クイズ・テスト・過去問復習）

- `quiz.timeLimitSec`（難易度☆1〜☆5の制限時間）は 20・30・40・55・70秒。設計の 10〜60秒から 40HzP の依頼でそれぞれ10秒延ばした。制限時間があるのはクイズ・過去問復習の解き直し・補習（1問ずつ出す）で、テストには無い
- 勉強のメニューのボタン（クイズ・テスト・過去問復習・補習・作問）は、テストのジャンルのボタンと同じ形（40HzP の依頼「ボタンにもデザインを」）：アイコン（`menu_*`、16×16 を2倍）と、縁取りの色（クイズ＝オレンジ・テスト＝青・過去問復習＝緑・補習＝山吹・作問＝紫）。アイコンはクイズ＝早押しボタン、テスト＝赤い「100」の答案、過去問復習＝間違いノート（左のページの×を右のページで○）、補習＝黒板、作問＝「？」の電球。絵と色は Claude Code の判断（色は `study.js` の `MENU_LOOK`、絵はエディタで `menu_*` を直す）。形は `study.js` の `tintButton`（CSS の `.tint-btn`）
- 過去問復習（40HzP の依頼「正誤問わず最新の10問とお気に入り5問を振り返れる仕組みに」）：勉強のメニューの「過去問復習」で、「最近解いた問題」と「お気に入り」を並べる（`study.js` の `renderReviewList`。解いた問題もお気に入りも無いうちは押せない）
  - 最近解いた問題：クイズ・テスト・解き直し・補習・孫の「なんで？」で答えた問題を、正解・不正解を問わず新しい順に `quiz.historySize`（10）問まで。同じ問題は新しいほうだけ（`quiz.js` の `pushHistory`）
  - お気に入り：`quiz.favoritesMax`（5）問まで。1問ずつの結果の画面・採点した答案・過去問復習の札の「☆ お気に入りに入れる」で入れる（もう一度押すと外す）。いっぱいのときは入らず、外してから入れるよう知らせる（`toggleFavorite`）。採点した答案のボタンはツイートの画像には出さない
  - 札は問題文を2行まで見せ、押すと開いて、問題文の全部・自分の答え（○×。大喜利は書いた文、時間切れ）・正解と解説・お気に入りのボタンを出す（`reviewLists`）
  - それぞれ「解き直す」で、並んだ問題を上から順に1問ずつ（制限時間つき）解き直せる。数え方はふつうの勉強と同じ（`createSession` の `pool`）
  - セーブの `knowledge.history`（`{ id, correct, chosen, oogiri }` の新しい順）と `knowledge.favorites`（問題id）。知識なので生まれ変わっても残る。前のセーブは空から始まる
  - 前の過去問復習（間違えた問題・騙された問題を解き直し、正解すると外れる）はやめた。間違えたままの問題（`knowledge.review`）は数え続けていて、心理統計学の画面だけに出る
- クイズと過去問復習の解き直しは、はじめは問題文だけを出す（40HzP の依頼）。読み終わって「選択肢を表示する」を押すと選択肢が出て、そこから制限時間が減り始める（押すまでは時間切れにならない）。孫の「なんで？」も同じにした（Claude Code の判断。同じ1問ずつの制限時間つきの問題なので）。押したボタンの場所に選択肢が出るので、出てから0.3秒は選べない（続けて2回押しても答えたことにならない。`study.js` の `reveal`・`REVEAL_GUARD_MS`、`ui/nande.js`）

  - 孫の「なんで？」（`nande: true`。40HzP の依頼。設計ページ「全ジャンルからランダムに『なんで？』と聞いてくる」）：孫と戦っている間、出てから `balance.json` の `nande.firstSec` 秒後、以後 `intervalSec` 秒ごとに、全ジャンルから1問（勉強のクイズと同じ選び方）を画面全体に出す。出している間はゲームの時間が止まる。答えはふつうの勉強と同じに数える（熟練・累計正解数・過去問復習）。正解すると孫に最大HP×`nande.correctDamageRatio`（10%）のダメージ（防御が崩れる前は0）、間違い・時間切れだと孫のHPが最大HP×`wrongHealRatio` 回復する（`sim.js` の `askWhy`・`nandeAnswered`・`nandeUnanswered`、`ui/nande.js`）。勉強の正解では敵にダメージは入らない（すぐ下）が、孫の「なんで？」は戦いの仕掛けなので、正解のダメージを残した（Claude Code の判断）。孫はふつうの攻撃もする
- 中ボスを倒したときのミニムービー（ほかに、体の不調と寿命のミニムービーがある。下の「寿命と転生」）：`monsters.json` の `defeatMovie`（文の並び）がある中ボスを倒すと、画面全体が暗転して、主人公とその中ボスが向き合う絵（今の世界の背景を切り抜いたもの）の下に文を1つずつ出す。文字は少しずつ出て、タップで進む（途中でタップすると全部出る）。最後の文のあとタップで暗転して戻る。流れている間はゲームの時間を止め、知らせは終わってから出す（`ui/movie.js`、`ui/scenes.js` の `startMovie`）。ムービーと孫の「なんで？」は `ui/notices.js` の `runOverlay` が1つずつ順に出す（「なんで？」の正解で倒したときは、閉じてからムービー）。冒険で倒しても孫の「なんで？」の正解で倒しても流れる。勉強画面で問題を解いている最中（問題が出ていて、まだ答えていない間。テストは用紙を提出するまで）は、ミニムービー（中ボス・体の不調・寿命）を出さずに取っておき、答え終わったら（または勉強画面を離れたら）出す（40HzP の依頼。`ui/scenes.js` の `afterAnswering`、`study.js` の `answering`）。寿命が来たときは、答えるまでゲームの時間が止まるので制限時間も減らない。孫の「なんで？」は取っておかない（数秒ごとに来るので、ためると重なる）。小学校教師の2つの文は 40HzP の依頼。ほかの8人の文は、小学校教師の「次は中学校教師と…」に続く形で Claude Code が書いた仮の文（40HzP が直してよい）。デバッグ画面から流し直せる
- 中ボスの防御は、累計の正解数（`knowledge.totalCorrect`。中ボスが出る前の正解も数える）が `monsters.json` の `unlockCorrect` に届くと崩れる（設計書4.7の「出てから5問正解」を 40HzP の依頼で変えた）。足りていれば出てきた時点で攻撃が効く

## balance.json の項目（設計書に無いもの）

- 設計書に無い項目：
  - `floor.spawnLeadSec` 次の群れを、主人公の次の攻撃の何秒前に出すか（下の「攻撃のテンポ」）。ザコは1階層分（`monstersPerFloor` 体）がまとめて出る
  - `quiz.testQuestions` テストの問題数、`quiz.dailyProgress` 今日の1問に正解したときに進む熟練の問題数（下の「今日の1問」）、`quiz.historySize` 過去問復習の最近解いた問題の数、`quiz.favoritesMax` お気に入りの数
  - `midboss.expMultiplier`・`goldMultiplier` 中ボスの経験値・ゴールドの倍率、`ally.hpFromBoss` 仲間になったときのHPの倍率
  - `hero.base`・`hero.perLevel` の `mp`（MP）・`wis`（賢さ）。`hero.wisPerCorrect` 正解1回で増える賢さ
  - `hero.expBonusPerCorrect` 正解1回で上がる経験値の倍率（倍率＝1＋累計の正解数×この値。敵を倒したときの経験値に掛ける。不正解では下がらない）
  - `hero.attackIntervalSec` 主人公の攻撃の間隔（0.5秒＝秒間2回）
  - `spell` 主人公の全体攻撃「ひらめき」：敵が `minTargets` 体以上でMPが `mpCost` 以上あると使う。ダメージ＝賢さ×`power`（防御は効かない）。MPは毎秒 `mpRegenPerSec` 回復し、眠ると全回復
  - `birthday` 誕生日の熟練判定：`upChance` この1年に勉強したジャンルが上がる確率、`downChance` 勉強していないジャンルが下がる確率、`idleYears` 下がるのは何年以上勉強していないジャンルか（下の「誕生日の熟練判定と階層の移動」）
  - `life` 寿命（`lifespanYears`±`lifespanSpread` 歳）と、体の不調を感じ始める年（寿命の `ailmentYearsBefore` 年前）、`hospital` 病院の治療（1回で延びる年数 `extendYears`、治療費 `treatmentCosts`。治療費の数が受けられる回数）、`reincarnation.multiplier` 世代ごとの倍率、`reincarnation.proficiencyCapStep` 生まれ変わるたびに上がる熟練Lvの上限、`rocket.buildCost` ロケットの建造費、`rocket.stepYears` ロケットの工程1つにかかるゲーム内の年数、`rocket.launchSuccessRateMax` 試作機で上がる本番の成功率の上限、`rocket.prototype` 試作機（`cost` 1回の費用・`successRate` 成功率・`dogBonus`／`otherBonus` 成功したときに本番の成功率が上がる量（犬／ほかのザコ）・`stepYears` 実際に宇宙を飛んだ生き物で進む工程の年数）、`barn.joinChance` ザコを倒したときになついて飼育小屋に入る確率（動物行動学を専攻にしていると `ethologyJoinChance`）、`barn.ethologyAffinityRate` 動物行動学を専攻にしているときの懐き度の上がり方の倍率、`barn` のそのほか（`affinityMax`・`affinityPerYear`・`affinityPerCorrect`・`affinityPerTouch`・`affinityPerFlight`・`friendlyAffinity`・`giftGoldKills`・`seeOffMax`）は懐き度（下の「飼育小屋と試作機」の「懐き度」）
  - `fields` 学際分野：`unlockLevel` 解放と休眠の境目の熟練Lv、`shopDiscount` 行動経済学の店の値引き（0.2＝2割引）
  - `nande` 孫の「なんで？」の間隔（`firstSec`・`intervalSec`）と、正解したときの孫へのダメージ（最大HPに対する割合 `correctDamageRatio`）、答えられなかったときに孫が回復する割合（`wrongHealRatio`）
  - `advisor` 顧問（下の「顧問」）：`slots` 場所ごとに置ける人数、`citationsPerYear` 要出典の回数（誕生日に戻る）、`periodicTestProgress` 定期テストで多く進む問題数、`hrStaffBonus` 人事で社員の効果が増える割合、`rocketSubsidy` 補助金で建造費が安くなる割合、`taxCut` 税務顧問で法人税が安くなる割合
  - `authoring` 作問権（下の「作問」）：`rightsLevel` 作問権に要る熟練Lv、`rightsGenres` その熟練Lvのジャンルの数
  - `corporation` 法人化（下の「会社」）：`profitBonus` 法人化した会社の利益が増える割合、`taxRate` 法人税の割合（今年の法人の利益に掛ける）
  - `boss` ボスの強さ：その階層のザコの数値に `hpMultiplier`・`atkMultiplier`・`defMultiplier`・`expMultiplier`・`goldMultiplier` を掛ける
  - `rocket.launchSuccessRate` 打ち上げの成功率、`moon.floorOffset`・`rampFloor`・`rampTo` 月面の敵の強さ（月面F階層＝地球の floorOffset＋F 階層の強さ×月面の倍率。下の「月面」）。`moon` のそのほか（`smoothDamage`・`splashAtkMultiplier`・`sinkIntervalSec`・`splitAt`・`absorbSec`・`remainsSec`）は月面のボスの仕掛け（下の「月面」の表）。`moon.transportPerKg` 補給所の輸送費（重さ1kgあたり）、`moon.radioCharge` 電波望遠鏡の頁が開くまでの正解の数、`moon.relaySec` 通信基地の返事が届くまでの秒数（下の「月面の街」）
- 主人公の名前は `hero.name`（8文字まで。最初の案内と施設で決める）
- 品物は `items.json`、魔物は `monsters.json`、契約できる仲間は `recruits.json`

## 店（装備）

40HzP の依頼「装備を追加して」。設計ページ「学習・テスト・クイズの報酬で店の品揃えが増える」「ゴールドを消費して装備を手に入れる」

- 装備の枠は武器・防具・装飾品の3つで、1つずつ付けられる（`sim.js` の `EQUIP_SLOTS`。セーブの `equipment` に `accessory` を足した。前のセーブは「なし」で読める）。ステータスは付けている品の分だけ足される（`heroStats`）
- 品物は `items.json`。どれも勉強の累計正解数（`unlockCorrect`）で入荷し、ゴールドで買う。品ぞろえ（名前・数値・値段・入荷は Claude Code の判断。40HzP が直してよい）

  | 枠 | 品物（足すステータス／値段／入荷に要る累計正解数） |

  | 武器（攻撃） | 木の剣（6／30／0）・銅の剣（15／150／5）・鉄の剣（30／800／15）・鋼の剣（50／5,000／30）・玉鋼の刀（75／2万／50）・ダマスカス鋼の剣（105／6万／80）・オリハルコンの剣（150／18万／120） |

  - 2026-11-08 にすばやさと運の良さを無くしたとき（上の「数値の調整」）、革の靴（前はすばやさ10）・四つ葉のクローバー（運の良さ15）・疾風のマント（すばやさ45）・賢者の石（前は賢さ80・すばやさ30・運の良さ40）を今の数値に付け替えた。名前・値段・入荷・見た目・アイコンはそのまま。数値は Claude Code の判断（足す数の合計が、前の品より大きくなるように）
- 買うと、同じ枠の今の装備より強ければ（足すステータスの合計が大きければ）自動で付ける。持っている品は店の「装備する」でいつでも付け替えられる（`buyItem`・`equipItem`）
- 店の画面（`ui/facility/shop.js` の `shopPanel`）は、武器・防具・装飾品の見出しごとに、入荷した品をアイコン付きで並べる。まだ入荷していない品は枠ごとに次の1品だけ、アイコンの影絵と「勉強で正解 あと◯回で入荷」を出す。主人公のステータスに今の装備を出す
- アイコンは `item_<品物のid>`（16×16、`style-guide.md` 12章）。`items.json` の `icon` に名前を書く
- 生まれ変わると装備も持ち物も最初から（入荷は累計正解数なので、2世代目からはすぐ全部入荷している）
- 月面だけの品（`items.json` の `moon: true`。設計ページ「月面の街」）：宇宙服（防具。受けるダメージ−20%、30億G）・金のバイザー（装飾品。攻撃+10%、10億G。前は会心の一撃+10%）・月面車の車輪（装飾品。HP+15%、20億G。前はすばやさ+15%）。数値を足すのではなく割合で効く（`effects`：`damageCut`・`atkRate`・`hpRate`。`sim.js` の `heroStats`。地球の固定の数値の装備は、月面のレベルでは差が出ないため）。月面の補給所でだけ買え、月面に来ればすぐ入荷している。地球に持ち帰れる（地球の店にも、持っている月面の品は「装備する」で並ぶ）。割合で効く品は地球のどの品より強いとみなして、買うと付け替える（月面の品どうしは付け替えない）。見た目：宇宙服＝白い服にオレンジのえり、金のバイザー＝目に金色のレンズ、月面車の車輪＝灰色の靴。数値はすべて仮（設計ページ「試遊で合わせる」）
- 品物の重さ（`weight`、kg）：月面の補給所では、値段が「本体＋輸送費（重さ×`moon.transportPerKg`）」になる（`transportCost`・`itemBodyPrice`・`itemPrice`）。重さは Claude Code の判断（剣は1〜3kg、鎧は5〜30kg、四つ葉のクローバーは1g など）
- 装備の見た目（40HzP の依頼「装備に合わせて見た目も変わるようにして」）：冒険画面（と勉強画面の小さな冒険の様子）・街の主人公・主人公のステータスの絵が、付けている装備で変わる。主人公の絵（`hero_*`・`heroine_*`）を、`items.json` の品物の `look` に合わせてゲームが塗り替える（`outfit.js` の `dressFrames`。絵のファイルは書き換えない。性別と装備の組み合わせごとに1回だけ作る。`ui/assets.js` の `heroLooks`）
  - 武器：剣の色が変わる（`look` の `tip` 刃の先・`blade` 刃・`guard` つば・`guardLight` つばの光。鉄の剣はもとの絵の色）。武器を付けていないと素手で殴る（剣を消して手の輪郭を描き足す）。剣を持つのは若い姿の待機と攻撃だけで、年を取った姿は杖のまま
  - 防具：服とズボンの色が変わる（`light`・`cloth`・`shade` 服の明・中・暗、`collar`・`collarLight` えりとマフラー）。防具なしはいつもの青い服。年を取った姿も変わる
  - 装飾品（`look.type`）：`shoes` 靴の色（革の靴）・`brooch` えりの飾り（四つ葉のクローバー＝緑、賢者の石＝赤）・`glasses` 目にレンズの光（学者のメガネ）・`cape` 背中のマフラーを伸ばしたマント（疾風のマント）
  - 色の組み合わせは Claude Code の判断（40HzP が `look` の色のキーを直してよい）：木の剣＝茶・銅の剣＝銅色・鋼の剣＝青白い刃と銀のつば・玉鋼の刀＝白い刃と黒いつば・ダマスカス鋼の剣＝黒っぽい刃と真ちゅうのつば・オリハルコンの剣＝青緑の刃と金のつば。布の服＝緑・革の鎧＝茶・鉄の鎧＝明るい灰・鎖かたびら＝暗い灰・鋼の鎧＝白と水色・武者の大鎧＝赤と金のえり・オリハルコンの鎧＝青緑と金のえり
  - 塗り替えは主人公の絵の色の分け方で決まる（`style-guide.md` 3章「主人公の絵の色の決まり」）。主人公の絵を手直しするときもこの分け方を守れば、装備の見た目はそのまま効く。`outfit.test.js` が「武器・防具ごとに見た目がちがう・素手に剣が残らない・装飾品はどの姿でも見える」を確かめる
  - 変えないもの：あやまる・赤面する絵（教室のミニモーション）。最初の案内の性別のボタンの絵は、生まれたばかりの何も装備していない姿（素手）
- 品物を足すとき：`items.json` に1件足し（同じ枠では後の品ほど強く・高く・入荷を遅く。見た目の `look` と重さ `weight` も書く）、アイコンを描く。`items.test.js` が「枠・並び・アイコン」を確かめる。強い品を足すと進み方と中ボスに勝てるレベルが変わるので、上の「数値の調整」と中ボスの表を計算で確かめ直す

## 仲間が集まる場所（契約）

- 施設画面に最初から出ている。`recruits.json` の仲間（戦士・格闘家・魔法使い・僧侶）と契約できる（40HzP の依頼。設計書の第1段階は仲間の一覧だけだった。設計ページの「ゴールドを消費して仲間を手に入れる」を、ゲーム内の月ごとの契約にした）
- 契約すると最初の1か月分（`monthlyCost`）をその場で払い、以後はゲーム内の1か月（`HOURS_PER_MONTH`＝8760÷12時間）ごとに払う。払えないと契約が切れて去る。解約はいつでもできる（払った分は戻らない）
- 強さは主人公に合わせて伸びる：攻撃＝主人公の攻撃×`atkRatio`。`role` は `attack`（先頭を攻撃）・`all`（敵全体を攻撃）・`heal`（主人公のHPを最大HP×`healRatio` 回復）。`intervalSec` は行動の間隔
- 契約した仲間はセーブの `allies` に `hired: true` と次の支払い日 `paidUntil` を持つ。中ボスだった仲間（契約料なし）と同じ配列
- スプライトは `ally_<id>_idle`（大人の頭身・右向き）。冒険画面では主人公の後ろに、パーティーの仲間を並べる
- 中ボスだった仲間は、仲間が集まる場所の「中ボスだった仲間」の欄で、パーティーに「入れる」「外す」をいつでも選べる（40HzP の依頼）。外した仲間は控えになり、戦わず、冒険画面にも出ない。街の施設の顧問にもできる（下の「顧問」）。冒険画面の上は「仲間 ◯（控え◯・顧問◯）」。セーブでは控えの仲間だけ `benched: true` を持つ（無ければパーティーにいる。前のセーブはそのまま読める）。契約した仲間は対象外（やめるときは解約）。`sim.js` の `setInParty`・`partyAllies`
- パーティーは契約した仲間と合わせて `balance.json` の `ally.partyMax`（5人）まで（40HzP の依頼「戦うのも5人まで」）。戦うのも冒険画面に並ぶのもこの人数まで（並べる場所は `render.js` の `ALLY_SLOTS` の5か所なので、6人以上にするなら場所も足す）
  - いっぱいのときは「入れる」が押せず、新しく契約もできない（中ボスだった仲間を外すと契約できる）。いっぱいのときに中ボスを倒すと、その仲間は控えに入る
  - 前のセーブでパーティーが上限を超えていたら、読み込んだときに後ろの中ボスだった仲間から控えに回して知らせる（`fitParty`）

## 顧問（仲間にした中ボスの使い道）

40HzP の依頼「仲間になった中ボスの使い道を追加して」。設計ページ「専門職の人間」の「仲間にした後の役目（顧問）」を形にした。計算は `sim.js`（`setAdvisor`・`advisorActive`・`advisorsAt` と効果ごとの関数）と `quiz.js`、データは `monsters.json` の中ボスの `advisor`（`place`・`role`・`desc`）と `balance.json` の `advisor`

- 仲間にした中ボスは、街の施設に「顧問」として置ける。置いている間はパーティーから外れて戦わない（冒険画面にも出ない）。効果は1人1つで、置く場所は中ボスごとに決まっている
- 置ける人数は場所ごとに `advisor.slots`（今はどこも1人）。学校には3人の先生のうち1人だけなので、誰を置くかを選ぶ（設計ページ「誰を置くかが戦略になる」）
- 置く・やめさせるは、仲間が集まる場所の「中ボスだった仲間」の欄と、置く施設の「◯◯の顧問」の欄のどちらでもできる。やめさせると、パーティーに空きがあればパーティーに、なければ控えに戻る。パーティーに「入れる」と顧問ではなくなる
- セーブでは顧問の仲間だけ `advisor: true` を持つ（前のセーブはそのまま読める）。仲間なので、生まれ変わると最初から
- 学校と研究室は「学校・研究室」の建物（前の「専攻の付け替え」の建物。街に空きが無いので、専攻の付け替えと一緒にした。Claude Code の判断）

  | 中ボス | 置く場所 | 役目 | 効果 |
  |---|---|---|---|
  | 小学校教師 | 学校 | 補習 | 破りすてたテストの問題（`knowledge.torn`）を集めて出す（勉強のメニューに「補習」。1問ずつ・制限時間つきで、出し方はクイズと同じ）。正解した問題は補習から外れる（顧問がいなくても、ほかの勉強で正解すれば外れる） |
  | 中学校教師 | 学校 | 定期テスト | テストで全問正解すると、そのジャンルの熟練の進みが `periodicTestProgress`（1）問分多くなる（`gradeTest` の `session.periodic`） |
  | 高校教師 | 学校 | 進路指導 | 未解放の学際分野のうち、解放にいちばん近いもの（足りない熟練Lvの合計が少ないもの）の「？」（もう片方のジャンル）を、学校・研究室の専攻の欄で教える（`fieldList(state, ctx, guide)` の `hint.other`） |
  | 大学教授 | 研究室 | 予習 | 次に戦うボス（今いる世界で、この人生でまだ倒していない、いちばん手前の階層のボス。`nextBoss`）の「当時の根拠」（`whyBelieved`）を、戦う前に学校・研究室と図鑑で見せる |
  | 学会の査読者 | 研究室 | 要出典 | 問題を出したとき、口を挟んでいる魔物がいれば、俗説の選択肢（誤答1）に「要出典」の印を付ける。誕生日までに `citationsPerYear`（3）回まで、誕生日に戻る（`state.citationsUsed`。`quiz.js` の `citeMyth`） |
  | 就職面接官 | 会社 | 人事 | 社員が会社の利益を増やす効果が `hrStaffBonus`（25%）大きくなる（`hrFactor`） |
  | 税務調査官 | 会社 | 税務顧問 | 法人化した会社の決算（税金イベント）で、法人税が `taxCut`（半分）になる（`corporateTax`。下の「会社」の法人化） |
  | 政治家 | ロケット発射場 | 補助金 | ロケットの建造費の `rocketSubsidy`（1割）を肩代わりする（`rocketBuildCost`。打ち上げ許可の工程は肩代わりしない） |

  - 設計ページの文との違い：小学校教師の「正解すると『怒られる』が消える」は、このゲームでは破りすてた瞬間に怒られる（上の「テスト」）ので、作っていない。就職面接官の「向き不向きが見える」は、会社の画面に前から「よく効く」と出ているので、効果を大きくするほうだけにした。要出典の回数（設計ページ「数は試遊で決める」）、人事・補助金の数字は Claude Code の判断
  - ロケットの目安への影響：顧問なしの目安（下の「会社」「寿命と転生」）は変わらない。毎回の人生で22歳から就職面接官と政治家を顧問に置き、病院の治療もすべて受けると、2世代目の75歳ごろに建造費（2700億）に届く（治療を受けないなら3世代目の45歳ごろ）。法人化（30歳から）と税務調査官（45歳から）も足すと、2世代目の73歳ごろ（治療なしなら2世代目の79歳ごろ）。計算で再現した
  - `advisor.soon`（「◯◯ができてから」）を書いた中ボスは、その仕組みができるまで置けない（今は無い。前は税務調査官に書いていた）
- 孫は仲間にならないので顧問にもならない
- 顧問を足すとき：`monsters.json` の中ボスに `advisor` を書き、効果を `advisorActive(state, ctx, id)` を見て書く。場所を足すなら `sim.js` の `ADVISOR_PLACES` と `balance.json` の `advisor.slots`、置く施設の画面に `advisorSection`（`ui/facility/advisor.js`）。`advisor.test.js` が確かめる

## 会社（起業）

40HzP の依頼。設計ページの「仲間と一緒に起業してお金を生み出す速度を上げる」「会計士がいると効率が上がる」「事務員・営業（会社に入れると業績が上がる）」を形にした（企画は 40HzP の依頼で足した）。

- 経営学の熟練レベルが1以上で、街の「会社」が使えるようになる（`business.json` の `unlock`）。それまで会社は「準備中」で、中には説明（`town.json` の `desc`。「経営学の熟練レベルが1以上で解放」を入れてある）と今の経営学の熟練レベル、選べる業種の名前を出す（`ui/facility/common.js` の `LOCKS`）。もう会社があれば、あとで熟練が下がっても入れる
- 会社はいくつでも持てる（同じ業種は1つまで）。業種は経営学の熟練レベルで解放され、レベルが上がるほど利益の大きい業種が選べる（`business.json` の業種の `level`）。レベルごとに3つずつ、15業種（40HzP の依頼で増やした）

  | 経営学 | 業種（元手／1か月の利益・社員なし／よく効く社員） |
  |---|---|
  | 1 | 飲食店（1.2万／1,200／営業）・出版社（1.4万／1,400／企画）・学習塾（1.3万／1,300／事務員） |
  | 2 | 建設会社（33万／1.1万／事務員）・旅行会社（30万／9,900／営業）・広告代理店（36万／1.2万／企画） |
  | 3 | 製薬会社（1,100万／8.8万／会計士）・音楽レーベル（860万／7.2万／企画）・法律事務所（960万／8万／事務員） |
  | 4 | IT企業（1.4億／60万／企画）・銀行（1.6億／66万／会計士）・自動車メーカー（1.3億／54万／営業） |
  | 5 | 総合商社（17億／430万／営業）・エネルギー会社（19億／480万／事務員）・宇宙開発企業（21億／530万／会計士） |

- 数の目安：ロケットの建造費（3000億G）に、勉強を続けて3世代目に届くように合わせた（40HzP の依頼「3世代目くらいでロケット」）。計算の前提：経営学は12年ごとに+1（1世代目は12歳でLv1）、心理学は14年ごと、業種に関係するジャンルは20年ごとに上がり、生まれ変わっても前世のLvから熟練Lvの上限（5・10・15）まで上がり続ける。届く業種のうち利益の一番大きいものを起業し、社員はいちばん優秀な質で雇う。結果：1世代目の最高所持金 約256億、2世代目 約2,190億（届かない）、3世代目は55歳で届く（勉強がもっと遅い前提では3世代目の66歳）。`life.test.js` が「1世代目は遠い・2世代目は届かないが近づく・3世代目の50〜75歳で届く」を確かめる。業種の数字を変えてこのテストが落ちたら、目安がずれている

- 社員（会計士・営業・企画・事務員。`recruits.json` に `role: "staff"`）は会社ごとに1人ずつ雇う（会社の画面で）。契約の仕組み（最初の1か月分をその場で払い、以後1か月ごと。払えないと去る。やめられる）は戦う仲間と同じ。戦わず、パーティーにも入らない。仲間が集まる場所には出さない（案内の文だけ）
- 社員の質（`business.json` の `staffGrades`：新人・中堅・ベテラン・エース・精鋭・伝説）は心理学の熟練レベル（`staffGenre`）で上がる（40HzP の依頼）。雇うときは、今雇えるいちばん優秀な質で雇う。もういる社員は「◯◯に替える」で、より優秀な社員に入れ替えられる（前の社員の払った分は戻らない）。質が上がるほど効果（`bonusMultiplier`）も契約料（`costMultiplier`）も大きい
- 会社1つの1か月の利益＝業種の `monthlyProfit` ×（1＋社員の効果の合計）×（1＋関係するジャンルの熟練Lvの合計×`genreBonusPerLevel`）×世代の倍率。社員の効果＝`profitBonus`×質の `bonusMultiplier`×（業種の `specialty` なら `specialtyMultiplier`）。全部の会社の利益が、時間がたつと少しずつ所持金に入る。社員の契約料は別に払う（`sim.js` の `companyProfit`・`companiesProfit`・`earnCompany`）
- 業種の関係するジャンルは、設計ページの「業種は熟練済みのジャンルから選ぶ（例：製薬＝化学＋生物、出版＝現代文）」に合わせた。熟練していなくても起業はできる（熟練しているほど利益が増える）
- たたむと元手は戻らず、その会社の社員との契約も終わる。同じ業種をまた起業できる
- 法人化（40HzP の依頼「法人化を作って、税務調査官も使えるようにして」。設計ページ「法と経済学（法学＋経済学）：会社を法人化できる。収益が上がる代わりに税金イベントが起きる」）
  - 学際分野の法と経済学を専攻にしている（休眠していない）と、会社の画面の会社ごとに「法人化する」が出る。費用はかからず、やめられない。法人化したあとで専攻から外しても法人のまま（`sim.js` の `incorporate`・`canIncorporate`）。会社の名前は「株式会社◯◯」になる
  - 法人化した会社は、1か月の利益が `corporation.profitBonus`（50%）増える（`companyProfit` の `corpBonus`）
  - 税金イベント（決算）：年齢が1つ上がるたびに、その1年に法人化した会社が稼いだ利益（`tax.earned`）の `corporation.taxRate`（30%）を法人税として払う。税務調査官を会社の顧問に置くと半分（上の「顧問」）。足りなければ払えるだけ払い、残り（`tax.owed`）はこのあとの会社の利益から先に払う（`settleTaxes`・`corporateTax`）。決算のたびに知らせが出る。会社の画面の上に、今年の法人の利益と次の決算の法人税の見込みを出す
  - 法人税を引いても、法人化したほうが少し得（1.5×0.7＝1.05倍）。税務調査官がいると1.5×0.85＝1.275倍。数字は Claude Code の判断（設計ページに数字は無い）
  - 社員の契約料は法人税の計算から引かない（利益に比べてごく小さいので）
  - ロケットの目安への影響：顧問なしで法人化だけすると、3世代目の53歳ごろ（しないときは55歳）。治療も受けると3世代目の46歳ごろ（しないときは47歳）。`life.test.js` の目安（法人化しない遊び方）は変わらない
  - セーブ：会社に `corp: true` と `incorporatedAt`、`state.tax`（`{ earned, owed, year }`。`year` は前に決算した年齢）。前のセーブは既定値で読める。生まれ変わると会社と一緒に最初から
- セーブでは `companies`（`{ uid, industry, foundedAt, staff: [{ id, grade, paidUntil }] }` の並び）と `nextCompanyUid`。版2→3 で、前の会社1つ（`company`）と社員（`staff`）をここに移した（社員は新人として。会社が無いのに雇っていた社員は契約を終えた）
- 冒険画面の上に「会社（業種、または◯社）の利益 1か月 +◯G」を出し、手取り（ゴールド＋会社の利益−契約料）に入れる
- 業種を足すとき：`business.json` に1件足す（`level` は経営学の熟練、`specialty` は社員の id、`genres` は問題ジャンルの名前）。`business.test.js` が「Lv1は3つ・Lvが上がるほど利益が大きい」などを確かめる

## 寿命と転生（世代）

40HzP の依頼。設計ページ「年齢・寿命（基本80歳）」「主人公が寿命で死んだら別キャラとして生まれ変わり、前世の記憶と能力を引き継ぐ」を形にした。

- 寿命は生まれるたびに `balance.json` の `life.lifespanYears`（80）±`lifespanSpread`（3）歳で決まる（`lifespanFor`）。寿命の年齢になると生まれ変わる（`sim.js` の `reincarnate`）。80歳は現実で約3時間20分
- 最初からになるもの：Lv・経験値・ゴールド（40HzP の依頼）。あわせて、品物と装備・仲間（中ボスだった仲間も契約も）・会社・中ボス（また7歳から会う）・ボス（前世で倒したボスにもまた会う。40HzP の依頼。下の「階層とボス」）・階層・年齢も最初から（新しい人生なので）
- 引き継ぐもの：知識（熟練・累計正解数・過去問復習（最近解いた問題・お気に入り）・間違えたままの問題・破りすてた問題・直近の出題・解放した学際分野と専攻・熟練の記録）・図鑑・称号（`legacy.titles`）・名前・ロケット計画の工程と試作機で上がった成功率（`legacy.rocket`）・飼育小屋のザコ（`legacy.barn`。40HzP の判断）。足場（構造工学）はボスと一緒に最初から
- 世代の倍率（40HzP の依頼）：生まれ変わるたびに `reincarnation.multiplier`（1.5）倍。2世代目は1.5倍、3世代目は2.25倍。掛かるのは、ステータスの伸び（`hero.perLevel` の全部と `wisPerCorrect`。初期値の `base` には掛けない）・敵を倒したときの経験値とゴールド・会社の利益（`generationMultiplier`）。セーブの `life.generation`
- 熟練Lvの上限（40HzP の依頼）：1世代目は5（`genres.js` の `MAX_PROFICIENCY`）。生まれ変わるたびに `reincarnation.proficiencyCapStep`（5）ずつ上がる（2世代目10・3世代目15…。`sim.js` の `proficiencyCap`）。勉強の正解でも誕生日の判定でも上限まで上がる。業種は経営学Lv5、社員の質は心理学Lv5（伝説）でいちばん上なので、6から先は関係するジャンルとしての会社の利益（`genreBonusPerLevel`）が増え続ける。難易度の出し方は Lv5 の割合のまま
- 体の不調と病院（40HzP の依頼「街に病院を追加して、70歳前後で身体の不調を感じ始めるミニムービー」。設計ページ「寿命は医者や生化学で延びる」）
  - 寿命の `life.ailmentYearsBefore`（10）年前に、体の不調を感じ始める（寿命は80±3歳なので67〜73歳。`sim.js` の `ailmentAge`）。一度だけミニムービーが流れる：年を取った主人公（`hero_old_idle`。白髪・ひげ・杖）が1人で今の世界に立ち、文を出す。文は `town.json` の病院の `ailmentMovie`。今は 40HzP の依頼の1文「歳を取り、体の不調を感じ始めた。街の病院で一度診てもらおう。」だけ（文を足すと順に出る。`{name}` に名前、`{age}` に年齢が入る）。終わったら「街に病院がある…」と知らせる（`ui/scenes.js` の `startAilmentMovie`）。デバッグ画面から流し直せる
  - 不調はムービーと表示だけで、ステータスは変わらない（Claude Code の判断。進み方を変えないため）。主人公のステータスの「寿命」に「体の不調を感じている」と出る
  - 不調を感じ始めてからは、冒険画面（と勉強画面の小さな冒険の様子）の主人公が年を取った姿になる（40HzP の依頼）。待機は杖をつき（`hero_old_idle`）、攻撃は杖を振り上げて前に突く（`hero_old_attack`、若い主人公の攻撃と同じ 24×16）。`sim.js` の `heroLooksOld`。生まれ変わると若い姿に戻る。街と主人公のステータスの絵はいつもの姿のまま
  - 病院（街の右下）：不調を感じ始めてから治療を受けられる。1回ごとに寿命が `hospital.extendYears`（2）年延びる。治療費は `hospital.treatmentCosts` の順（10万・100万・1000万G）で、1つの人生で3回まで（最大+6年）。不調のあとは診察で「あと◯年ほど（◯歳ごろまで）」が分かる（`treatmentInfo`・`receiveTreatment`・`lifespanOf`）。治療の中身・回数・値段は Claude Code の判断（設計ページは「数値は試遊してから調整する」）
  - 治療で延びるのは `life.lifespan`（生まれたときの寿命）ではなく、治療の回数 `life.treatments` から出す（不調の年齢は動かない）。セーブの `life.ailing`（不調を感じ始めたか）と `life.treatments`。前のセーブは足りない項目を既定値で埋めるので、版は上げていない。生まれ変わると両方最初から
  - ロケットの目安への影響：毎回すべての治療を受けても、2世代目の最高所持金は約2,740億で届かず、3世代目の47歳で届く（受けないときは55歳）。`life.test.js` が「治療を受けても2世代目では届かない」を確かめる
  - 会社を持っていない人の70歳の所持金はおよそ14万〜60万G（勉強なしで約25万、1分に1問で入荷した装備を全部買っていくと約14万、装備を鉄までにして貯めると約60万）なので、1回目の治療は受けられ、2回目からは会社の利益が要る
- 寿命が来たら、ミニムービー（年を取った主人公の絵）で前世をふり返り（何歳・Lv・最高階層・残したゴールド）、最初の案内（年齢と名前を選ぶ）をもう一度出す。案内の上に「◯世代目。前世の記憶を受け継いだ。…◯倍」を出し、名前は前世のものを入れておく。年齢を選ぶまで時間は止まる
- 最初の案内の年齢（40HzP の依頼「ゲーム初回起動時の年齢選択では7歳を選択できないようにして」）：ゲームを初めて始めるとき（1世代目）は「0歳から始める」だけ。「7歳から始める」のボタンは押せず（薄く出る）、下に「生まれ変わると選べる」と出る。生まれ変わったあとの案内では両方選べる（`sim.js` の `canStartAt`）。設計ページの「初回起動時と転生時に、0歳から始めるか7歳から始めるかを選択させる」の、初回だけを変えた
- 性別（40HzP の依頼「初回起動時と転生時、性別を選択できるようにして」）：最初の案内（初めて始めるときと生まれ変わったとき）で「男の子」「女の子」を選ぶ。ボタンにそれぞれの主人公の絵が付く。はじめは男の子、生まれ変わったときは前の人生の性別を選んでおく（選び直せる）
  - 変わるのは見た目と先生の呼び方だけで、強さは同じ（Claude Code の判断）。主人公の絵は男の子が `hero_*`、女の子が `heroine_*`（同じ6つ・同じ大きさ。`ui/assets.js` の `heroSets` と `main.js` の `app.heroSprites`）。大喜利のミニムービーで先生が呼ぶ「◯◯君」は、女の子なら「◯◯さん」（`sim.js` の `honorific`、`oogiri.js` の `{kun}`）
  - セーブの `hero.gender`（`male`・`female`。`sim.js` の `GENDERS`）。前のセーブは男の子として読む。生まれ変わっても残り、案内で選び直す（`startGame` の5つ目の引数）
  - デバッグ画面の「年齢」の欄の「性別を切り替える」で、もう片方の絵をすぐ確かめられる
  - 案内は、縦の短い画面（生まれ変わったときの「◯世代目」の行で高くなる）では案内の中をスクロールして全部見られる（CSS の `#intro .dialog`）
- 前世のまとめは `legacy.lives`（主人公のステータス画面に直近3つを出す）。冒険画面の名前の横に「（◯世代目）」、主人公のステータスに「世代」と「寿命（80歳前後）」
- 冒険画面の上（日付と今の階層の行の下）にも「最高到達 ◯階層（世界の名前）」。同じ行の右に、月面に行っていれば「月面◯階層」、前世のほうが深ければ「歴代最高 ◯階層（◯世代目）」（入りきらない小さい画面では次の行へ。40HzP の依頼。前は「これまで ◯階層」だったが、40HzP の「意味が伝わりにくい」「歴代最高のほうがいい」で変えた。`ui/adventure.js`）
- 主人公のステータスの「最高到達地点」（40HzP の依頼）：この人生でいちばん深く進んだ地球の階層とその世界（月面に行っていれば月面の階層も）。生まれ変わったあとは「歴代最高は◯階層（◯世代目）」（前世も含めた最高）と、それが何世代目か（この人生なら「この人生」）も出す（`sim.js` の `farthestReached`。この人生の最高は `life.maxFloor`・`life.moonMaxFloor`、前世は `legacy.lives` の `maxFloor`・`moonFloor`）
- 設計ページとの違い：設計ページは「前世の記憶と能力を全て引き継ぐが、仲間との関係値と戦闘ステータスは0に戻る」。Lv とゴールドを失い、世代ごとに1.5倍になるのは 40HzP の依頼。装備・仲間・会社・中ボスを最初からにしたのは Claude Code の判断（ゴールドを失うので、ゴールドで買ったものも最初から）

## ロケット発射場

- 設計ページ「ロケット計画」の工程を並べる。工程は生まれ変わっても残る（設計ページ「工程ごとに完了を保存する」「転生をまたいでもよい」。`legacy.rocket`）
- 建造費（`balance.json` の `rocket.buildCost`＝3000億G。40HzP の依頼。政治家を顧問に置くと補助金で1割安い。上の「顧問」）はゴールドで払う。ゴールドは生まれ変わると無くなるので、1つの人生のうちに貯めて払う（`sim.js` の `payRocketBuildCost`）
- 機体設計（航空宇宙工学）・エンジン・推進剤（燃焼工学）・軌道計算（軌道力学）・打ち上げ許可（宇宙法）は、その学際分野を専攻にしていて休眠していない間、ゲーム内の時間で進み、`rocket.stepYears`（5年、現実で約5分）で完了する。専攻は2枠なので同時に2つまで。工程と学際分野の対応は `fields.json` の `rocketSteps`（`sim.js` の `rocketSteps`・`advanceRocket`）。進み具合は `legacy.rocket.steps`（工程id → 進んだゲーム内の時間）
- 建造費とすべての工程が終わると「打ち上げる」が押せる。打ち上げは無料で何度でもできる（建造費は一度払えばよい。Claude Code の判断）。成功すると月面へ（下の「月面」）
- 打ち上げは `rocket.launchSuccessRate`（80%）で成功する（設計ページに数字が無いので Claude Code の判断）。試作機で上がった分（`legacy.rocket.rateBonus`）を足し、`rocket.launchSuccessRateMax`（95%）まで（`launchSuccessRate`。下の「飼育小屋と試作機」）。失敗すると地球に残り、`fields.json` の `rocketSteps` で `redoOnFailure` の工程（エンジン・推進剤）だけ0に戻る（設計ページ「失敗するとエンジン・推進剤の工程だけやり直し」）。成功率は確率論（数学＋統計学）を専攻にしていると見える（設計ページ「確率論があれば成功率が見える」）。押すと確認を出す（`sim.js` の `launchInfo`・`launchRocket`）
- 打ち上げと着陸はミニムービー（`ui/launch.js`）：3・2・1 で火がつき、打ち上げ場（`scene_launchpad`）から飛び立って、暗転のあと月面の街の発着場に降りる。失敗は少し浮いて火が消え、落ちて煙に包まれる。タップで飛ばせる。流れている間はゲームの時間が止まる
- 有人（生命維持＝生化学）はまだ作っていない（設計ページでは「有人にする場合」の任意の工程）
- 大きな数は「◯億」「◯兆」で出す（`ui/dom.js` の `fmt`）

## 月面（ロケットで行く階層）

40HzP の依頼「ロケット打ち上げで行ける月面ステージを作って、月面の街は地球の街と別にして、地球に帰るための無料ロケットも置いて」。中身は設計ページ「ザコ：月面（ロケットで行く階層）」「小ボス：月面（月の研究史をたどる）」

- 月面は地球とは別の階層列（設計ページ「月面は地球側とは別の階層列」）。セーブの `adventure.world`（`earth`・`moon`）で今いる世界を持ち、`adventure.floor` は今いる世界の階層。もう片方の世界の階層は `earthFloor`・`moonFloor` に取っておく（`sim.js` の `goToWorld`）。打ち上げると月面の1階層から（前に行っていればその階層から）、帰ると打ち上げた地球の階層から
- 月面の敵の強さ：月面F階層＝地球の（`moon.floorOffset`＋F）階層のザコの数値（`strengthFloor`）に、月面の倍率を掛けたもの（`sim.js` の `moonRamp`・`floorStats`。HP・攻撃・防御・経験値・ゴールドのすべて。ボスはこれに `boss` の倍率）
  - `floorOffset` は300。ロケットに届くのは3世代目の50歳前後で、そのころの地球の最高階層はおよそ290（勉強なし）〜390（1分に1問）なので、月面1階層がその少し手前の強さになるようにした（Claude Code の判断）
  - 月面の倍率（40HzP の依頼「月面60階だけ強くするのではなく、月面1階から段階的に強くして」）：月面1階層は1倍で、1階層ごとに同じ割合（約1.13倍）ずつ上がり、`moon.rampFloor`（60）階層で `moon.rampTo`（1400）倍。61階層から先は1400倍のままで、地球の階層の伸びの分だけ強くなる。倍率＝rampTo^((F−1)÷(rampFloor−1))
  - 地球の「式を掛け算に戻さない」（上の「数値の調整」）は地球の階層の話。月面は、世代ごとに1.5倍ずつ（と、引き継ぐ累計正解数の経験値の倍率で）強くなる主人公に合わせて、わざと掛け算にした。1世代でおよそ月面6〜7階層ずつ先へ進める
  - 目安（計算で再現。1分に1問正解・仲間4人と契約・装備を買う・40歳で打ち上げ、打ち上げたときに月面だけの品を3つとも買う（会社の利益で買える額）。累計正解数は前世から引き継ぐ）

## 誕生日の熟練判定と階層の移動

## 学際分野（ジャンルの組み合わせ）

## 画面の色と設定

- ふだんの画面（勉強・図鑑・街の施設の中・設定・デバッグ、案内・今日の1問・孫の「なんで？」などの窓）は、明るい紙の色に濃い字（40HzP の依頼「勉強画面・図鑑画面などの基本背景を明るくして」。前は暗い紫）。色は `css/style.css` の一番上の `:root`：`--bg` 背景・`--panel` 枠の中・`--panel2` ボタン・`--line` 枠線・`--text` 字・`--muted` 薄い字・`--accent` 見出しなどの濃いオレンジ・`--accent-bg` ボタンを塗る明るいオレンジ、ほかに正解・不正解の選択肢、魔物が口を挟む枠、図鑑の絵の下地、お気に入りの☆の色。色の値は Claude Code の判断（40HzP が直してよい）
- ダーク（40HzP の依頼「設定でダークモードも選択出来るようにして」）：下の切り替えバーの「設定」（歯車のアイコン `icon_settings`。`ui/settings.js`）で「明るい色」「ダーク」を選ぶ。はじめは明るい色。ダークは前の暗い紫の色（`:root[data-theme="dark"]` で上の色を全部決め直している。明るい色に色を足したら、ダークにも同じ名前で足す。`settings.test.js` が確かめる）
  - 設定はセーブとは別に、この端末に覚える（localStorage の `plrpg.settings`）。生まれ変わっても、セーブを消しても残る。セーブの形は変えていない
  - 読み込みの途中で色が一瞬変わらないように、`index.html` の先頭の小さなスクリプトが同じ名前を読んで先にダークにする
  - 設定の画面には、今は画面の色だけ。設定を足すときは `ui/settings.js` の `normalizeSettings` に既定値を足す（図鑑の並べ方 `zukanSort` も、ここに一緒に覚えている。下の「図鑑の並べ方」）
- 下の切り替えバーは、どちらを選んでもコルクボードの板（40HzP の依頼「隣のボタンとの境目がわかりやすいデザインにして」「木目をやめてコルクボード風にして」。その前は「木目調にして」「年輪が見えるような感じがいい」で木目の板だった）。ボタン1つずつが1枚の板で、板と板の間は暗い茶色のすき間（コルクボードの木の枠のつもり）、板の縁は左上が明るく右下が暗い（盛り上がった板）。板の絵はドット絵 `ui_tabs_cork`（40×28・3枚、category `texture`。茶色の地に大きめのこげ茶の粒（40HzP の依頼「粒を大きくして」で直径3〜4ドットに、「地の色をもう少し暗くして文字を読みやすくして」で地を砂色から茶色にした）。3枚で粒の並びがちがう）。`ui/assets.js` が2倍にして、ボタンの順に1枚目・2枚目・3枚目・1枚目…と各ボタンの背景にする（CSS の `--board`）。字はクリーム色にこげ茶の縁取り。選んでいる画面は板がへこみ（暗くなり、縁の明暗が逆）、上に金色の線、字は黄色。ダークのときは板を少し暗くする。模様はエディタで `ui_tabs_cork` を直せば変わる（枚数を増やすと、その数の板を順に使う。高さを変えるとボタンの高さ56pxとずれる。`tabs.test.js` が確かめる）
- どちらを選んでも暗いままのもの：冒険画面（絵の上のステータス）・街の絵（建物の名札と上の帯）・知らせ・ミニムービー（中ボス・寿命・ロケット・破りすてる・大喜利）。ドット絵の上で読みやすいように、ダークと同じ色を入れている（`style.css` の同じ所）
- 明るい画面では、パレットの明るい色（山吹・水色・ピンクなど）を字の色に使わない。テストのジャンルのまとまりの名前は、字を濃くして左に色の印を付けた

## 図鑑の並べ方

40HzP の依頼「図鑑の魔物をソートしたい。例えばジャンル別とかで」。図鑑の上の「並べ方」のボタンで選ぶ（`ui/zukan.js` の `zukanGroups`）。まとまりごとに見出しと「出会った ◯/◯」を出す

- 種類順（はじめ）：地球のザコ・月面のザコ・ボス・中ボス。`monsters.json` の並びのまま（前からの並び）
- ジャンル別：魔物の最初のジャンル（`genres` の先頭）で分ける。並びと見出しの色の印は、テストのジャンル選びと同じ（`genre-groups.json` のまとまりの順と色）。中ボス（ジャンルが無い）は最後。まだ出会っていない魔物も、影絵のままそのジャンルに並ぶ（出現エリアと同じく、どのジャンルを勉強すれば会えるかの手がかり。Claude Code の判断）
- 出現エリア別：地球のザコは最初の出現エリア（`areas` の先頭）、地球のボスはいる階層の世界（110階層から先のボスは天空の神殿）。世界の順のあとに月面（ザコとボス）、中ボス
- 名前順：出会った魔物をあいうえお順。まだ出会っていない魔物は名前が分からないので、最後に元の並びでまとめる
- 月面を踏破すると開く頁と、月の裏側から聞こえた宇宙の頁（上の「月面の街」）は、どの並べ方でもいちばん下
- 選んだ並べ方は、画面の色の設定と一緒にこの端末に覚える（`plrpg.settings` の `zukanSort`。上の「画面の色と設定」）。並べ方を足すときは `settings.js` の `ZUKAN_SORTS` と `zukanGroups` に足す。`zukan.test.js` が「どの並べ方でも魔物が全部1回ずつ出る」などを確かめる

## 施設画面（街）

- 下の切り替えバーはコルクボードの板（上の「画面の色と設定」）。「冒険」「勉強」「街」「図鑑」「設定」には、字の上にアイコンを付けている（40HzP の依頼。冒険＝剣、勉強＝用紙と鉛筆、街＝家並み、図鑑＝本と虫めがね、設定＝歯車。16×16 を2倍で出し、選んでいない画面のアイコンは少し暗くする。ボタンの高さは前と同じ 56px）。スプライトの名前は `index.html` のボタンの `data-icon` に書く（`ui/assets.js` が読んでボタンの頭に入れる。無ければ字だけ）。`tabs.test.js` がスプライトがそろっているかを確かめる
- 施設画面は「街」（下の切り替えバーの名前も「街」。40HzP の依頼。中の名前は `facility` のまま）。`bg_town`（90×160）の上に施設の外観（`town_<施設>`、32×32、category `building`）を並べ、真ん中の道の下の小さな広場に今日の1問の掲示板（`town.json` の `board`）、その上の道に主人公が立つ（右下にあった噴水の広場は病院にした。広場に主人公が立っていたのを、掲示板を置くために道へ動かした）。設計ページ「施設画面の表示」の「施設を並べる」を、40HzP の依頼で街の見た目にした

- 広場の掲示板をタップすると、今日の1問（下の「今日の1問」）。道の主人公をタップすると、主人公のステータスと名前の変更（どちらの絵も装備に合わせた姿。年を取った姿は冒険画面とムービーだけ）。街の上の帯に所持金と版を出す
- 図書館（`library`、`town_library`。寝床の跡。2026-11-07）：熟練の記録（下の「誕生日の熟練判定と階層の移動」）。設計ページの「放置で眺める暗記資料」は準備中。寝床（テントで眠る）はやめた
- 施設の中にいるときは、知らせを画面の下に出す（上の「← 街へ」を隠さない）
- 施設を足すとき：スプライトを描き（`style-guide.md` 9章）、`town.json` に1件足す。中身を作ったら `PANELS` に足す

## 階層とボス

- 階層に上限はない（設計書4.1の「9階層を越えたら9階層を繰り返す」は、40HzP の依頼で外した）。敵は階層ごとに強くなり続ける
- 画面の表記は「ボス」（40HzP の依頼。設計書・設計ページの「小ボス」のこと。図鑑・冒険画面・知らせ・学際分野の説明などすべて）
- ボス（かつての学説）は `monsters.json` に `kind: "boss"` で書く。設計書に無い項目：
  - `floor` 出る階層（設計ページでは10階層ごと）
  - `whyBelieved` なぜ信じられたか、`overturnedBy` 誰がどう覆したか（図鑑で正体と一緒に開く）
- ボスのいる階層ではボスだけが1体で出て、倒すと次の階層へ進む。中ボスが待っているときは中ボスが先
- 一度倒したボスは、その人生ではもう出ない（セーブの `bosses`）。その階層はザコの階層になる。ボスは仲間にならない
- 生まれ変わると、前世で倒したボスにもまた会う（40HzP の依頼。前は生まれ変わっても倒したままだった）。`reincarnate` で `bosses` を空にする。図鑑（正体など）は残り、もう載っているボスを倒しても「図鑑に載った」とは知らせない（`bossDefeated` の `learned`）
  - 前の版のセーブ（2世代目以降）は、読み込んだときに、この人生の最高階層（`life.maxFloor`）かそれより先の階層の「倒した」ボスを、前世で倒したものとしてまた出るようにする（ボスを倒すと次の階層に進むので、この人生で倒したボスは最高階層より手前にいる。`sim.js` の `forgetPastLifeBosses`）
- ボスのスプライトは 32×32（`style-guide.md`）。ゲームは幅が16より大きい敵を右寄りに1体で描く
- ボスを問題に干渉させるには、Notion の問題の「関連する魔物」にボスの名前を書き、誤答1に「当時その学説が信じられた根拠」を入れる（設計ページ「誤答選択肢との関係」）

## 10階層ごとの世界（背景）

- `stages.json` の `from`（その世界が始まる階層）ごとに背景が変わる。`sim.js` の `stageFor` が、`from` がその階層以下で一番大きい世界を選ぶ
- 今は100階層まで：はじまりの草原（1〜）・生き物の森（11〜）・平安京（21〜）・錬金術の工房（31〜）・ピラミッドの砂漠（41〜）・火山（51〜）・氷の大地（61〜）・夜の都会（71〜）・海の底（81〜）・天空の神殿（91〜）。101階層から先は天空の神殿のまま
- 設計ページ「10階層ごとに世界観をジャンル単位で切り替える」に合わせ、`genre` に世界のジャンルを書いた（今は表示に使っていない）。月面は「ロケットが無いと行けない」階層なので、地球の階層の続きではなく、`world: "moon"` の別の世界にした（上の「月面」）
- 背景は `bg_floorNN`（NN はその世界の最初の階層。90×160、`style-guide.md` 6章）。ボスはそれぞれの世界の最後の階層（10・20・…・100）にいる
- 新しい世界の最初の階層に入ると「◯階層　◯◯に入った」と知らせる
- 世界が変わるときは0.5秒の暗転を挟む（40HzP の依頼）。前半0.25秒で暗くなり、真っ暗の瞬間に背景を入れ替え、後半0.25秒で明るくなる。暗くなるのは冒険画面のキャンバスだけで、ステータスの表示は暗くならない。ゲームの時間は止めない。ボスを倒して進んだときのほか、やられて戻ったとき・階層を移動したとき・セーブを読み込んだときも同じ。起動した直後は暗転しない。長さは `render.js` の `STAGE_FADE_SEC`（`createStageFade`）
- 世界を足すとき：背景を描き、`stages.json` に1件足す。`stages.test.js` が「1階層から始まる・背景がある・大きさが合う」を確かめる。その世界に出るザコも決める（下の「ザコの出現エリア」）

## ザコの出現エリア

- 地球のザコは、`monsters.json` の `areas`（10階層ごとの世界の名前。`stages.json` の `name`）に書いた世界にだけ出る。冒険の群れは、今いる世界のザコから選ぶ（`sim.js` の `zakoPool`。計算に世界の一覧 `ctx.stages` を渡す）

- 今いる世界に出られるザコが1体もいなければ、地球のザコ全体から選ぶ。天空の神殿（91階層〜）より先も天空の神殿のザコが出続ける（101階層から先に世界を足すときに分け直す。設計ページ）

- 図鑑：まだ出会っていない地球のザコの札に「出現：はじまりの草原（1〜10階層）」のように世界と階層の範囲を出す（`areaLabels`。最後の世界は「天空の神殿（91〜階層）」）。月面のザコは前から「月面で待っている」
- ザコの強さは階層で決まり、ザコごとに違わないので、進み方（遊んだ時間ごとのレベルと最高階層）は変わらない

## 今日の1問（日替わりの問題）

40HzP の依頼「その日初めて起動したら、冒険画面に『今日の1問』の札を出して。タップでその日の出題日の問題を1問出す。閉じたら街の掲示板に残す。クイズに挑戦するときも、毎日初回は『今日の1問』が出題されるようにして。正答で熟練度が5/10進むようにして」。計算は `quiz.js`（`dailyQuestionFor`・`refreshDaily`・`dailyPending`・`dailyInfo` と、`createSession`・`answer` の中）、画面は `ui/daily.js`

- 日付は端末の時計の日付（`dayKey`。'YYYY-MM-DD'）。起動したとき・遊んでいる途中（30秒ごと）・画面に戻ってきたときに見て、日付が変わっていればその日の今日の1問に入れ替える（`main.js` の `refreshDaily`・`checkDay`。途中で変わったときは「日付が変わった」と知らせる）
- どの問題か：問題リストの「出題日」（`questions.json` の `date`、'MM-DD' で毎年くり返す）がその日の問題。同じ日の問題が2問以上あれば、その中から日付で決まる1問。その日の問題が無ければ、出題日の無い問題から日付で決まる1問（`dailyQuestionFor`）。同じ日なら誰が何度開いても同じ問題
  - 2026-10-29 の同期で、出題日のある問題が366問になり、2月29日も含めて1年の毎日に1問ずつある（`check-questions.mjs` が「今日の1問：◯/366日」と、問題の無い日・2問以上ある日を警告に出す）
- 冒険画面の札：その日に初めて起動すると、ステータスの下に白い紙の札（「今日の1問　10月29日　記念日」「タップで出題」）が出る。押すと画面全体に出題する（クイズと同じく、はじめは問題文だけ。「選択肢を表示する」で選択肢が出て制限時間が減り始める。「あとで答える」で閉じられる）。出している間はゲームの時間が止まる
- 閉じると札は消え、街の掲示板に残る（答えていなくても。`markDailyOpened`）。掲示板を押すと同じ画面で、まだなら答えられ、答えたあとは自分の答え・正解と解説を読める。掲示板の絵は3枚：何も貼っていない（札をまだ開いていない）・紙が貼ってある・答えた赤い丸の印
- 出題日のある問題も、メインジャンルのふつうの問題として出る（40HzP の依頼「今日の1問で出す問題はメインジャンルに合わせて通常の問題リストにも入れて」）：クイズ・テスト（そのジャンルの問題数にも入る）・過去問復習・補習・孫の「なんで？」のどれにも出る。ただし、その日の今日の1問は、答えるまでほかの出し方ではなるべく出さない（先に答えてしまわないように。`quiz.js` の `dailyAvoid`。そのジャンルにほかの問題が無ければ出る）
- クイズ：その日の今日の1問にまだ答えていなければ、クイズの1問目は今日の1問（勉強のメニューの「クイズ」に「今日の1問から」と出る。問題の上に「今日の1問（10月29日・記念日）」）。孫の「なんで？」・テスト・過去問復習・補習では出さない
- 数え方：答えはその日に1回だけ（札・掲示板・クイズのどれで答えても同じ。間違い・時間切れでも答えたことになる）。正解すると、そのジャンルの熟練が `balance.json` の `quiz.dailyProgress`（5）問分進む（ふつうの正解は1問分。10問分で Lv が1つ上がる）。そのほかはふつうの正解と同じ（累計正解数・経験値の倍率・過去問復習・図鑑）。記念日は、その日の出題日の問題のときだけ出す
- セーブの `legacy.daily`（`{ day, id, opened, result }`）。現実の日付のことなので、生まれ変わっても残る。前のセーブは「まだ」から始まる
- デバッグ画面の「今日の1問」：日付を選んで「やり直す」と、その日の札がまた出る（ほかの日の問題を試せる。選んだ日付は読み込み直すまで続く）
- `daily.test.js` が確かめる

## 作問（ユーザーの問題の受付）

40HzP の依頼「ユーザーの作問を受け付けてデータベースに追加してチェックを出来るようにして、問題が採用されたら作問者のユーザーにどの問題が採用されたかをわかるようにして」。設計ページ「機能」の「ユーザーによる作問申請」

- 受付は Notion の「作問の受付」データベース（設計ページの下。上のリンク）。ユーザーはその「作問フォーム」（ウェブに公開したフォーム。Notion のアカウントは要らない）から送る。ゲームは通信せず、勉強画面の「作問」のボタンでフォームを別のページとして開くだけ（`data/submit.json` の `formUrl`。空のあいだは「準備中」）
  - 問題リストに直接は送らせない（いたずらやチェック前の問題が正本に混ざらないように。Claude Code の判断）
  - フォームで必ず書くこと（40HzP の依頼）：問題（問題文）・解答・メインジャンル（選択式。問題リストと同じ38ジャンル）・解説。ほかは任意：誤答1〜3・サブジャンル・難易度・関連する魔物・参照画像・ペンネーム・作問者コード（学際分野は、ユーザーが自由に書くのは難しいので 40HzP が列ごと消した）
  - 「必須」はフォームの設定で付ける（Notion の API では付けられないので 40HzP が付けた。問題文・解答・メインジャンル・解説の4つ）
  - フォームは「作問申請」。40HzP が「リンクを知っている全員」に公開したリンク（notion.site）を `submit.json` の `formUrl` に入れた（2026-10-21）。データベースの表のリンク（`app.notion.com/p/…?v=…`）はフォームではないので入れない（ログインが要り、公開すると送られた問題が全部見えてしまう）
  - フォームの質問の名前を変えると、データベースの列の名前も変わる。同期（下の「問題を同期して」）は列の名前で読むので、名前は変えない（2026-10-21 に題名の列「問題」が「解答」になっていたので、Claude Code が「問題」に戻した）
  - フォームの最初の質問は、40HzP が足した文字の列「問題文」（必須）。題名の列「問題」はフォームに出ないので、フォームから届いた行は題名が空（表では「無題」）。問題文は「問題文」の列で読む。「チェック待ち」の表に「問題文」を並べた
- チェック：「作問の受付」の「チェック」（未チェック → 確認中 → 採用／不採用）。「チェック待ち」の表に未チェック・確認中が並ぶ。直したいところは 40HzP がそのまま書き換えてよい
- 作問者コード：ゲームがはじめて起動したときに決まる8文字（例：K7Q2-9MXP。見まちがえやすい 0・O・1・I は使わない。`quiz.js` の `makeAuthorCode`・`ensureAuthorCode`）。セーブの `legacy.author.code`（生まれ変わっても同じ）。勉強画面の「作問」に出し、「コードをコピーして作問フォームを開く」でコピーしてからフォームを開く
- 採用の知らせ：問題リストから書き出した `questions.json` の問題が `author: { code, name }` を持ち、`code` が自分の作問者コードと同じ（大文字小文字・ハイフンのちがいは同じとみなす）なら、その人の問題（`adoptedQuestions`）。起動したとき、まだ知らせていない採用の問題があれば「あなたが作った問題が採用された！」と問題文を出す（一度だけ。知らせた問題は `legacy.author.seen`。`takeNewAdoptions`）。新しい版を公開すると、ゲームの「読み込み直す」で届く
- 勉強画面の「作問」に、採用された自分の問題を並べる。問題の解説の下に「作問：ペンネーム」（ペンネームが無ければ「みんなの作問から採用」）を出し、自分の問題なら「（あなたが作った問題）」と付ける
- 作問権（40HzP の依頼「作問権も作って」。設計ページ「作問権（いずれか2ジャンルをLv5）：そのジャンルの作問申請ができる。腕のある人だけが投稿するので審査の負担も減る」）
  - 熟練が `balance.json` の `authoring.rightsLevel`（5）以上のジャンルが `rightsGenres`（2）つそろうと、作問権がもらえる。作問できるのは Lv5 以上のジャンル。そのあと Lv5 に届いたジャンルも足していく（知らせが出る）（`sim.js` の `updateAuthorRights`・`authorRightsInfo`。毎回の `tick` で判定）
  - 一度もらったジャンルは、誕生日の判定で熟練が下がっても残る。知識なので生まれ変わっても残る（セーブの `knowledge.authorGenres`）
  - 作問権が無いうちは、勉強の「作問」でフォームを開けず、作問権までの進み具合（Lv5 のジャンルの数と、熟練の高いジャンル）だけを出す。作問権があると「作問権：◯◯・◯◯（フォームの『メインジャンル』は、このどれかに）」と出す
  - 作問権はゲームの中でフォームのリンクを見せるかどうかだけで決まる（フォームはゲームの外にあるので、リンクを知っている人は送れる。メインジャンルが作問権のジャンルかどうかも、フォームでは確かめられない）。チェックのときに 40HzP が見る
  - 学際分野（2つのジャンルの組み合わせ）ではなく、専攻に入れなくても働く（Claude Code の判断。設計ページは学際分野の一覧に書いているが、組み合わせが決まっていないため）
- まだ作っていないもの：ファンサーバーの「出題者」欄とスタッフロール
- セーブ：`legacy.author`（`{ code, seen }`）。前のセーブは既定値で読め、起動したときにコードが決まる
