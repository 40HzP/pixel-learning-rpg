# 「問題を同期して」と頼まれたとき（`questions.json` は手で編集しない）

2026-11-09 に CLAUDE.md から移した手順。文中の「上の◯◯」は `docs/decisions.md` の節。

0. 作問の受付を見る：「チェック」が「採用」の行を、問題リストに1件ずつ写す（同じプロパティ名のものはそのまま。「問題文」（空なら題名の「問題」）→ 問題リストの「問題」、ペンネーム → 「作問者」、作問者コード → 「作問者コード」）。写したら作問の受付の「チェック」を「反映済み」にする
   - 誤答1〜3か難易度が無い問題は、写しても書き出せない（下の「問題・解答・誤答が欠けているページは書き出さない」）。40HzP に「問題リストで誤答と難易度を埋めて」と、どの問題かを伝える（Claude Code が勝手に誤答を作らない）
   - 未チェック・確認中・不採用は写さない
1. Notion の問題リストを読む（Notion に接続できるなら直接。できなければ、40HzP に「問題リストを CSV で書き出して `game/data/notion-export/` に置いて」と頼む）
   - Notion の照会（SQL）はワークスペースで使える回数に上限があり、1時間ほどで戻る。上限に当たったら、問題リストの「同期用（全部）」ビュー（絞り込みの無い表。2026-10-29 に Claude Code が足した。消さない）を、ビューの読み出し（上限なし）で100行ずつ読む。作問の受付は「Default view」で読める
   - ビューで読んだ行は、空の列（サブジャンル・裏取りなど）が抜けて届く。書き出す列（問題・解答・誤答・解説など）は照会と同じ文字で届く（2026-10-29 に、509問すべてが前の書き出しと1文字も違わないことを確かめた）。前の書き出しに同じ id がある問題は、全部の項目を比べて変わったところだけを報告する
2. `questions.json` を書き出す。Notion のプロパティとの対応：

   | Notion | JSON |
   |---|---|
   | ページID（URL末尾の32文字を 8-4-4-4-12 に区切る） | `id` |
   | ` メインジャンル`（先頭に空白あり） | `genre` |
   | サブジャンル | `subgenres`（空なら `[]`） |
   | 難易度（☆の数） | `difficulty`（1〜5） |
   | 問題 | `question` |
   | ` 解答`（先頭に空白あり） | `answer` |
   | 誤答1・誤答2・誤答3 | `wrong`（**誤答1を必ず先頭**。誤答1が俗説の枠） |
   | 解説 | `explanation` |
   | 関連する魔物 | `monster`（空なら `null`） |
   | 作問者コード・作問者 | `author`（どちらかがあれば `{ "code": 作問者コード（空なら null）, "name": 作問者（空なら null） }`。どちらも無ければ書かない。コードが無いと作問者に採用は知らせられないが、ペンネームは解説に出る） |
   | 出題日 | `date`（'MM-DD'。空なら書かない。今日の1問に出す日） |
   | 記念日 | `anniversary`（空なら書かない。今日の1問の札に出す。「〜を借りる」と書いた行（その日の記念日ではない）は書き出さない） |

   - 問題・解答・誤答が欠けているページは書き出さない
   - メインジャンルは `game/js/genres.js` の問題ジャンル（設計ページ「問題ジャンル」）のどれかでないと検査が止まる。設計ページにジャンルが足されたら、`genres.js` にも同じ並びで足す（`genre-groups.json` のまとまりとアイコンも。上の「テスト」）（2026-10-19 に IT・情報・地理・文化・勉強法を足して33ジャンル、2026-10-21 に都市計画・気象学・哲学・美術・考古学を足して38ジャンルにした）
   - Notion の「学際分野」の列（2ジャンルの架け橋になる問題の学際分野名）は、まだゲームで使っていないので書き出さない
   - 「裏取り」「裏取りメモ」の列（今日の1問の裏取りの結果）も書き出さない。「要注意」の問題は報告に入れる（40HzP が出題日の前に確かめる）
   - 下の「同期しない問題」に書いたページは書き出さない（Notion にはページが残っている）
   - `generatedAt` に書き出した日時（日本時間）を入れる。インデント2、日本語はエスケープしない
3. 前世の記憶をたどる問題の候補 `game/data/first-check.json` を見直す：問題リストの☆で、関連する魔物が地球のザコ（⚠でない）で、裏取りが「出典確認済」の問題（`id`・`monster`・`genre`）。10〜15問にする。足りなければ☆の問題の裏取りを進めて足す（上の「最初の3分と前世の記憶をたどる」）
4. `node tools/check-questions.mjs` で検査する
5. 増えた問題・外した問題・警告を 40HzP に短く報告する（作問から採用して入った問題と、誤答が足りなくてまだ入らない問題も）
- 新しい「関連する魔物」が出てきたら `monsters.json` にも足す（設計ページの魔物系の節から。スプライトが無ければ `null`）。地球のザコには出現エリア `areas` も書く（設計ページの「ザコの出現エリア（一覧）」から。上の「ザコの出現エリア」）
  - 設計ページの魔物系の節に無い名前は足さない（検査の警告のまま。問題は出るが、口を挟む魔物はいない）
  - 図鑑の「俗説」の見出しは、魔物ごとに `mythLabel` で変えられる（ググンは「よくある間違い」。40HzP の依頼。「この俗説に◯回騙された」もこの言葉になる）。言葉の意味の魔物（`wordType: true`。ヤクブソク・オドロク）は「よく言われる意味」「本来の意味」
  - 設計ページの項目が「名前（ジャンル）：俗説 → 正体」のように名前の後ろにジャンルを書いていれば、`genres` はそのジャンルにする（節の見出しより優先。「言語学・鹿児島方言」の「鹿児島方言」のように問題ジャンルでない語は入れない）。2026-10-19 に 40HzP が足したググン（難読漢字）・トウホクリク（地理）・キタヒロ（地理）・チン（言語学）・デジカ（IT・情報）から。2026-10-29 に「ザコ：都市計画・気象学・哲学・美術・考古学（追加ジャンル）」の節の20体（ナシシンゴウ〜ナンオクネン。地球のザコ）を足し、ドット絵も描いた。2026-10-30 に「ザコ：勉強法」の8体（イチヤヅケ〜サンブンノニ）、「ザコ：生物」の21体（キノコショクブツは微生物）、カワイテカタマル（建築・化学）を足し、ドット絵も描いた。同じ日の2回目の同期で、問題に名前が書かれた61体（人体・微生物・心理学・物理・化学・熱力学・流体力学・地学・天体力学・日本史・世界史・言語学・現代文・古文・難読漢字・音楽学・音響工学・建築・法学の節。ジャンルは節の見出しのうち問題のメインジャンルに合うもの。⚠の付いたムペンバ・サンダンウチ・チョウタンバンコク・ハイレゾは `debated: true`、「本来の意味」を問う節の7体（カクシンハン・ナサケハ・ハテンコウ・コソク・イトヲカシ・ヤガテ・アリガタシ）は `wordType: true`）を足し、ドット絵も描いた。これで設計ページの地球のザコはタニンゴトのほかすべて入った
  - 照合のしかた：Notion の行を写し間違えないよう、Notion 側で行ごとに「問題・解答・誤答1〜3・解説・メインジャンル・難易度・サブジャンル・関連する魔物」を `|` でつないだ文字列の長さ・文字コードの和・位置で重み付けた和を照会し（再帰の SQL は使えないので、数の表を作って足し合わせる）、書き出した JSON から同じ計算をして全部が一致することを確かめる
- 同期しない問題（40HzP の依頼でゲームから外した。関連する魔物も `monsters.json` に足さない）
  - `3f9bafd0-61fe-81b5-bc6a-f0824e7dddfd`「他人事」の本来の読みは？（関連する魔物：タニンゴト）
  - `408bafd0-61fe-813a-b9fc-efadf2f57c26`「他人事」の本来の読みはどれ？（関連する魔物：タニンゴト。2026-10-30 に問題リストに入った同じ内容の問題。40HzP の依頼「タニンゴトは要らない」で、これも外す）
  - これから「関連する魔物」がタニンゴトの問題が入っても同期しない（40HzP の依頼「タニンゴトは要らない」。id をこの並びに足す）
- 外した問題がセーブの過去問復習（最近解いた問題・お気に入り）や間違えたままの問題に残っていても、起動時に `quiz.js` の `forgetMissingQuestions` が外す
